# Running the daily TrackSnarkPac update on a server

This is a runbook for whoever (person or agent) keeps the daily data update running. One run a day lists each channel's livestreams, downloads the chat replays of new ones, rebuilds `public/data`, and pushes to GitHub, where Actions publishes https://strawwaffle.github.io/TrackSnarkPac/.

A run takes a few minutes on a normal day. It sends roughly 10 to 20 requests to YouTube, at least 15 seconds apart.

## Requirements

- Linux with Python 3.10 or newer, `git` and outbound HTTPS. No other services.
- **A home or residential internet connection.** YouTube answers cloud and datacenter addresses (including GitHub's own runners) with "Sign in to confirm you're not a bot" when chat replays are requested. If the server is a rented VPS, expect exit code 75 every day; tell the owner instead of working around it.
- About 50 MB of disk.

## Rules

- **Never use YouTube cookies, logins or proxies**, and never lower the 15-second gap in `pipeline/youtube.py`. If YouTube blocks the runs, report it to the owner.
- **Commit only as StrawWaffle** (`StrawWaffle <355859478+StrawWaffle@users.noreply.github.com>`). Don't add co-author, "generated by" or other attribution lines, and don't put names, hostnames or paths from the server into commits or files.
- Only `update.py` commits, and it touches only `pipeline/state`, `public/data` and `public/avatars`. Don't force-push or rewrite history.

## One-time setup

1. **Deploy key.** Create a key that can push to this one repository and nothing else:

   ```sh
   ssh-keygen -t ed25519 -N "" -C tracksnarkpac-deploy -f ~/.ssh/tracksnarkpac_deploy
   cat ~/.ssh/tracksnarkpac_deploy.pub
   ```

   Send the **public** key (the `.pub` line) to the owner, who adds it to the repository as a deploy key with write access. Never send the private key anywhere. Then add to `~/.ssh/config`:

   ```
   Host github-tracksnarkpac
       HostName github.com
       User git
       IdentityFile ~/.ssh/tracksnarkpac_deploy
       IdentitiesOnly yes
   ```

2. **Clone and set the identity.**

   ```sh
   git clone git@github-tracksnarkpac:StrawWaffle/TrackSnarkPac.git ~/tracksnarkpac
   cd ~/tracksnarkpac
   git config user.name StrawWaffle
   git config user.email 355859478+StrawWaffle@users.noreply.github.com
   ```

3. **Python environment.**

   ```sh
   python3 -m venv pipeline/.venv
   pipeline/.venv/bin/pip install -r pipeline/requirements.txt
   ```

4. **Test without changing anything.** This lists the channels and prints any new streams, in about three minutes:

   ```sh
   pipeline/.venv/bin/python pipeline/update.py --list-only
   ```

   It should end with `N new past livestreams to fetch` and exit 0. Then do one real run, which also pushes if there's new data:

   ```sh
   pipeline/.venv/bin/python pipeline/update.py
   ```

5. **Schedule it daily.** With systemd (adjust `User` and paths):

   `/etc/systemd/system/tracksnarkpac-update.service`
   ```ini
   [Unit]
   Description=TrackSnarkPac daily data update
   Wants=network-online.target
   After=network-online.target

   [Service]
   Type=oneshot
   User=YOUR_USER
   WorkingDirectory=/home/YOUR_USER/tracksnarkpac
   ExecStart=/home/YOUR_USER/tracksnarkpac/pipeline/.venv/bin/python pipeline/update.py
   SuccessExitStatus=75
   TimeoutStartSec=4h
   ```

   `/etc/systemd/system/tracksnarkpac-update.timer`
   ```ini
   [Unit]
   Description=Run the TrackSnarkPac update daily

   [Timer]
   OnCalendar=*-*-* 06:00:00
   RandomizedDelaySec=20m
   Persistent=true

   [Install]
   WantedBy=timers.target
   ```

   ```sh
   sudo systemctl daemon-reload
   sudo systemctl enable --now tracksnarkpac-update.timer
   ```

   Without systemd, a crontab line works too: `0 6 * * * cd ~/tracksnarkpac && pipeline/.venv/bin/python pipeline/update.py >> ~/tracksnarkpac-update.log 2>&1`

## What a run does

`update.py` pulls the repo, lists every source in `pipeline/channels.json`, and for each past livestream it hasn't seen it downloads the chat replay. It stores superchats and gifted memberships in `pipeline/state/streams/<id>.json`, or records in `pipeline/state/missing.json` why there's no readable chat (members-only, no chat replay, age-restricted) along with the stream's date. It refreshes exchange rates once a day and fetches up to 60 missing or stale profile pictures (channels and cross-channel donors, re-checked every 120 days) into `public/avatars`. Then it rebuilds `public/data` with `build.py`, and commits and pushes only when streams, superchats, gifts, missing streams or pictures changed.

## Exit codes and what to do

| code | meaning | action |
|---|---|---|
| 0 | done, with or without new data | nothing |
| 75 | YouTube blocked a request; anything fetched before that was saved and published | nothing; the next run continues. If it happens several days in a row, tell the owner |
| 1 | error (network, git, YouTube changed something) | read the log; see below |

Logs: `journalctl -u tracksnarkpac-update` (systemd) or the cron log file.

- **Push rejected:** someone else pushed. Run `git pull --ff-only` and rerun. Don't force-push.
- **yt-dlp errors that aren't bot checks** (for example "Unable to extract", "Signature extraction failed"): YouTube changed something. Update yt-dlp to a release at least a week old, test with `--list-only`, and commit the new pin in `pipeline/requirements.txt` as StrawWaffle.
- **Exchange rate errors:** harmless; the previous rates are kept. `FXRATES_API_KEY` can be set in the environment if the keyless endpoint stops working.

## Adding a channel

The owner decides which channels are tracked. To add one, append an entry to `pipeline/channels.json`:

```json
{
  "name": "Channel Name",
  "slug": "channel-name",
  "url": "https://www.youtube.com/@Handle",
  "own_account": "@handle",
  "gift_price": 4.99,
  "lowest_tier": "name and local price of its cheapest membership level",
  "sources": ["https://www.youtube.com/@Handle/streams", "https://www.youtube.com/playlist?list=..."]
}
```

`gift_price` is the US price of the channel's cheapest membership level, which is what a gifted membership buys. Commit the change as StrawWaffle. The next run fetches the channel's whole history (about 20 seconds per stream, so a few hours for a big channel), and the site gives it a page, a place in the navigation and the next color. The site has validated colors for up to 8 channels.

## Running it on another machine

The same commands work on any machine with a clone of this repo, including Windows (`pipeline\.venv\Scripts\python pipeline\update.py`). Because every run pulls first and only stores what's new, a test run elsewhere doesn't conflict with the server; at worst the server finds nothing new that day.
